AM3 TWO-ESP32 PROJECT — COMPLETE RECHECK
Date: 2026-07-20

ARCHITECTURE
============
Display ESP32 <-> Hardware Host ESP32 <-> MQTT Broker <-> Mobile App

HARDWARE HOST NETWORK
=====================
- Starts the display Access Point before attempting router Wi-Fi.
- Operates continuously in WIFI_AP_STA mode.
- AP SSID: AM1-7AA010
- AP password: bitahomes
- AP IP: 192.168.4.1
- Display TCP port: 5050
- Router/STA and MQTT operate independently of the display AP.
- AP health is checked every 5 seconds.

DISPLAY NETWORK
===============
- Uses WIFI_STA only.
- SSID/password are hardcoded in AM3_DISPLAY/DisplayLinkConfig.h.
- Connects only to 192.168.4.1:5050.
- Reconnects Wi-Fi and TCP automatically.
- Sends authentication hello, heartbeat and optional start/stop/reset commands.

CORRECTIONS FROM THIS RECHECK
=============================
1. MQTT_MAX_PACKET_SIZE set to 2048 before PubSubClient include.
   The AM3 telemetry/config payload can exceed the library's normal small
   default packet buffer; without this, publish() can fail even while MQTT is
   connected.
2. Temperature-configuration JSON document and output buffer increased to 2048.
3. MQTT publish return values are checked and failures are reported on Serial.
4. PCF8574 read failure now returns 0xFF (idle HIGH) instead of 0x00.
   This prevents a missing/I2C-failed input expander from appearing as false
   LOW start/stop commands.
5. MQTT retry log corrected from "10 milliseconds" to "10 seconds".
