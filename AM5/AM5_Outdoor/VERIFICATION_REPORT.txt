AM5 OUTDOOR / SYSTEM SOURCE VERIFICATION
========================================

Corrected integration contract
-------------------------------
- Indoor/Outdoor RS485 protocol version: 2
- Status request 0x30: exactly 3 bytes
- Status response 0xB0: exactly 45 bytes
- Config set 0x31: exactly 12 bytes
- Config ACK 0xB1: exactly 2 bytes
- Config snapshot request 0x32: exactly 1 byte
- Config snapshot 0xB2: 2-byte header + 13 bytes per detected sensor
- Shared am5_rs485_protocol.h is byte-for-byte identical in Indoor and Outdoor.

Outdoor hardware behavior preserved
-----------------------------------
- Switch PCF8574: 0x26
- Relay PCA9554: 0x20
- ACTIVE-HIGH relays retained (HIGH ON / LOW OFF)
- Existing SW1..SW8 -> R1..R4 local relay logic retained
- Existing DS18B20 acquisition retained

Integration corrections
-----------------------
- Outdoor now reads status-request system_power from payload byte 1 and outdoorsw
  from byte 2; the previous code interpreted byte 2 as system power.
- Outdoor now sends every field at the byte offset Indoor actually parses,
  including individual switch states and separate relay/switch health flags.
- Active-HIGH PCA9554 startup is preloaded safely to relay OFF levels.
- Outdoor sensor offset rejects NaN/Infinity and runtime uses the exact persisted value.
- Wrong underscore-form device topic spelling removed from Indoor source.

Automated source-contract tests are provided/used during correction. Hardware
bench verification is still required after flashing because this environment
cannot electrically exercise the ESP32, RS485 transceivers, expanders, sensors,
router, mobile app, or display panel.
